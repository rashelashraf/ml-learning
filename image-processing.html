1. An image is a grid of numbers

Nothing about an image is special to a computer. It is a rectangular array of numbers, and every operation in this module is arithmetic on that array.

A grayscale image of height H and width W is an H × W matrix. Each entry is one pixel — short for picture element — and its value is a brightness. Position is given as (row, column), with the origin at the top-left, rows increasing downward.

Two coordinate conventions, one common bug

Array libraries index image[row, column], which is (y, x). Most drawing and geometry APIs take (x, y). Mixing them silently transposes your image or puts boxes in the wrong place, and it will not raise an error on a square image — which is exactly why it survives testing.

Pixel inspector

A 12 × 12 grayscale image. Hover or focus a cell to read the value the array actually stores. The shape you can see is nothing more than a region of high numbers next to a region of low ones.

The grid holds 144 numbers. A 1920 × 1080 photo holds just over two million per channel — the same idea, more of it.

2. Intensity, bit depth and dynamic range

What a pixel value means depends on its data type, and that is where most silent image bugs come from.

The common case is 8-bit unsigned integers: whole numbers from 0 (black) to 255 (white). Eight bits gives 28 = 256 distinct levels per channel. That is the bit depth. Scientific and medical imaging often uses 12- or 16-bit data, and rendering pipelines use floats.

TypeRangeLevelsWhere you meet it
uint80 – 255256JPEG, PNG, webcams, almost every dataset
uint160 – 6553565536Medical (DICOM), satellite, raw camera files
float32 [0, 1]0.0 – 1.0continuousModel input after scaling
float32 standardisedroughly −2.5 – 2.5continuousModel input after mean/std normalisation

Integer overflow wraps, it does not clip

Brightening a uint8 image by adding 50 turns a pixel of 220 into 14, not 255. Cast to a wider type, do the arithmetic, clip, then cast back.

import numpy as np

img = np.array([[220, 240]], dtype=np.uint8)

img + 50                                  # [[14, 34]]  wrapped around
np.clip(img.astype(np.int16) + 50, 0, 255).astype(np.uint8)   # [[255, 255]]

# Scaling to floats is a separate step from normalising
img_float = img.astype(np.float32) / 255.0        # now in [0, 1]

Contrast and dynamic range

Dynamic range is the spread between the darkest and brightest pixel actually present. An underexposed photo might only use values 0–60, so it looks flat even though 256 levels are available. Stretching that range back across the full scale is contrast stretching, and it is one of the cheapest preprocessing wins available.

# Min-max contrast stretch to the full 0-255 range
lo, hi = img.min(), img.max()
stretched = ((img - lo) / max(hi - lo, 1) * 255).astype(np.uint8)

3. Channels and colour

Colour is just several grayscale images stacked on top of each other, one per channel.

Grayscale — 1 channel

One brightness value per pixel. Shape (H, W). Smallest and fastest; fine when colour carries no signal.

RGB — 3 channels

Red, green and blue intensities that add to make a colour. Shape (H, W, 3). The default for natural images.

RGBA — 4 channels

RGB plus alpha (opacity). Shape (H, W, 4). Drop or composite the alpha before training or it becomes a phantom feature.

Multispectral — N channels

Satellite and medical imagery can carry dozens of bands, including infrared. Same array, larger last axis.

Channel splitter

The same picture, then each colour channel shown on its own as a grayscale image. A bright area in the red channel means that pixel has a high red value — nothing more.

Grayscale conversion is a weighted sum

Averaging the three channels is not how it is normally done. Human vision is far more sensitive to green than to blue, so the standard luminance formula weights them accordingly:

Y = 0.299 * R + 0.587 * G + 0.114 * B      # ITU-R BT.601 luma

gray = (0.299 * rgb[..., 0]
        + 0.587 * rgb[..., 1]
        + 0.114 * rgb[..., 2]).astype(np.uint8)

Other colour spaces

  • HSV (hue, saturation, value) separates which colour from how bright. Useful for colour-based thresholding, because a red object stays red-hued in shadow while its RGB values all drop.
  • LAB separates lightness from two colour axes and is designed so equal numeric distances look like equal perceptual differences.
  • YCbCr splits luma from chroma, which is what lets JPEG compress colour more aggressively than brightness.

4. Shape, memory layout and batching

Two frameworks, two conventions for the same array. Getting this wrong produces shape errors at best and quietly wrong results at worst.

LayoutShapeUsed by
HWC (channels last)(224, 224, 3)NumPy, PIL, OpenCV, TensorFlow
CHW (channels first)(3, 224, 224)PyTorch tensors
NHWC batched(32, 224, 224, 3)TensorFlow / Keras batches
NCHW batched(32, 3, 224, 224)PyTorch batches

N is the batch dimension: how many images are pushed through the model at once. Models are written to expect a batch, so a single image still needs that leading axis of size 1.

import numpy as np

img = np.zeros((224, 224, 3), dtype=np.uint8)   # HWC, one image

chw   = img.transpose(2, 0, 1)      # (3, 224, 224)   HWC -> CHW
batch = chw[np.newaxis, ...]        # (1, 3, 224, 224) add the batch axis

# In PyTorch the same two steps:
import torch
t = torch.from_numpy(img).permute(2, 0, 1).unsqueeze(0)
print(t.shape)                      # torch.Size([1, 3, 224, 224])

How much memory does a batch cost?

A batch of 32 RGB images at 224 × 224 in float32 is 32 × 3 × 224 × 224 × 4 bytes ≈ 19 MB for the input alone. The activations each layer keeps for the backward pass are typically many times that, which is why batch size is the first thing to cut when you hit an out-of-memory error.

5. Loading images in Python

Three libraries dominate, and they disagree about channel order.

import numpy as np

# --- Pillow (PIL): the general-purpose reader -------------------------
from PIL import Image

img = Image.open("cat.jpg")         # lazy: header only until you use it
print(img.size, img.mode)           # (640, 480) RGB   -- note (width, height)

img = img.convert("RGB")            # drop alpha / expand palette images
arr = np.asarray(img)               # (480, 640, 3) uint8, RGB order

# --- OpenCV: fast, and BGR by default --------------------------------
import cv2

bgr = cv2.imread("cat.jpg")                     # (480, 640, 3) uint8, BGR
rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)      # fix the channel order
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)    # (480, 640)

# --- torchvision: straight to a normalised tensor --------------------
from torchvision.io import read_image
tensor = read_image("cat.jpg")      # (3, 480, 640) uint8 CHW

The classic OpenCV bug

cv2.imread returns BGR, not RGB. Train on OpenCV-loaded data and infer on PIL-loaded data and your red and blue channels are swapped between the two. The model still runs, the loss still falls, and accuracy is quietly worse. Pick one convention and convert at the boundary.

Two more habits worth building: Image.open is lazy, so a corrupt file may only fail later — call img.load() or wrap reads in a try/except when scanning a dataset. And check img.mode rather than assuming: real datasets mix RGB, grayscale, palette and CMYK files, and a stray single-channel image will break a batch collation.

6. Resize, crop, flip and rotate

Models need every input the same size. How you get there changes what the model sees.

Resizing and interpolation

Resizing invents pixel values that were never measured, and the interpolation method decides how. Nearest-neighbour copies the closest pixel and keeps hard edges — the right choice for segmentation masks, where a label of 3 must not be averaged into 2.5. Bilinear and bicubic blend neighbours and look smoother, which is what you want for photographs.

from PIL import Image

img = Image.open("cat.jpg")

img.resize((224, 224), Image.BILINEAR)   # photographs
img.resize((224, 224), Image.NEAREST)    # label masks: never blend class IDs

# Preserve aspect ratio, then pad or centre-crop to the target
img.thumbnail((224, 224))                # in-place, keeps the ratio

Squash or crop?

Resizing a 1600 × 900 image straight to 224 × 224 stretches it and distorts every shape. The usual alternative is to resize the short side to 224 and centre-crop, which keeps proportions but discards the edges. Neither is free; choose based on whether your objects sit centrally and whether aspect ratio carries information.

Flips and rotations

Horizontal flips are cheap and usually safe for natural photos. They are not safe when orientation is meaningful: flipping a photo of text, a road sign, or a chest X-ray creates an image that could not exist. Rotation by an arbitrary angle also leaves empty corners, which have to be filled by reflecting, replicating the edge, or padding with a constant.

import cv2

flipped = cv2.flip(img, 1)                            # 1 = horizontal, 0 = vertical

h, w = img.shape[:2]
M = cv2.getRotationMatrix2D((w / 2, h / 2), 15, 1.0)  # 15 degrees about the centre
rotated = cv2.warpAffine(img, M, (w, h),
                         borderMode=cv2.BORDER_REFLECT)  # fill the empty corners

7. Convolution: the operation behind every filter

Slide a small matrix over the image, multiply, add up. Blur, sharpen and edge detection are all the same operation with different numbers — and it is exactly what a convolutional layer learns.

A kernel (or filter) is a small matrix, usually 3 × 3. For each pixel, line the kernel up on its neighbourhood, multiply each kernel weight by the pixel underneath, and sum the nine products. That sum becomes the output pixel. Do that for every position and you have convolved the image.

output[y, x] = sum over (i, j) of  kernel[i, j] * image[y + i - 1, x + j - 1]

Kernel playground

Pick a kernel and watch what it does to the same source image. The blur kernel is a local average; the Sobel kernels subtract one side of a pixel from the other, so flat regions cancel to zero and only edges survive. Each colour channel is filtered separately, which is why the edges come out tinted.

Padding, stride and output size

  • Padding — the kernel has no neighbours to read at the border. Adding a ring of pixels around the image (zeros, or a reflection of the edge) keeps the output the same size as the input.
  • Stride — how far the kernel moves each step. Stride 2 samples every other position and halves the output dimensions.
  • Output size for a square input: (W - K + 2P) / S + 1, where K is the kernel size, P the padding and S the stride.

Why this matters later

Hand-designed kernels like Sobel were how computer vision worked for decades. A convolutional network uses the identical operation but learns the nine weights from data, and stacks many such filters. When you reach the Deep Learning module, the convolution layer is this demo with the numbers filled in by gradient descent.

8. Histograms and thresholding

A histogram counts how many pixels hold each value. It is the fastest way to diagnose an image you cannot look at, one of several million in a dataset.

The shape tells you the exposure at a glance: bunched at the left means underexposed, a spike at 255 means blown-out highlights where information is gone for good, and two separated humps usually mean a bright subject on a dark background.

import numpy as np

hist, bins = np.histogram(gray, bins=256, range=(0, 256))

# Equalisation: redistribute values so the histogram is roughly flat,
# which pulls detail out of a low-contrast image
import cv2
equalised = cv2.equalizeHist(gray)

# Otsu picks the threshold that best separates the two humps
thresh, binary = cv2.threshold(gray, 0, 255,
                               cv2.THRESH_BINARY + cv2.THRESH_OTSU)

Thresholding turns a grayscale image into a binary mask: every pixel above the threshold becomes 1, everything else 0. It is the simplest possible segmentation, and it still works well for documents, microscopy and any scene with even lighting. When lighting varies across the frame, a single global threshold fails and adaptive thresholding — computing a local threshold per region — is the fix.

9. File formats and compression

The format decides whether the numbers you read back are the numbers that were written.

FormatCompressionGood forWatch out for
JPEGLossyPhotographs, large datasetsBlocky artefacts; re-saving degrades it again each time
PNGLosslessMasks, diagrams, screenshotsMuch larger files for photographs
TIFFEitherScientific, 16-bit, multi-pageWide variation in what readers support
WebP / AVIFEitherWeb delivery at small sizesOlder tooling may not decode them
Raw cameraNone or losslessFull sensor data before processingVendor-specific; needs a dedicated reader

Never store segmentation masks as JPEG

Lossy compression changes pixel values. In a photo you will not notice; in a mask where the value is the class label, a region of class 3 comes back as a smear of 2s, 3s and 4s with corrupted boundaries. Masks are PNG or TIFF, always.

10. The preprocessing pipeline

Putting it together: from a file on disk to a normalised batch the model accepts.

The order matters. Resize first so everything downstream is cheap and uniformly shaped, convert to float, then normalise last so the statistics apply to the values the model actually receives.

from torchvision import transforms

# ImageNet channel statistics - use these whenever you start from a
# model pretrained on ImageNet, so inputs match what it was trained on
IMAGENET_MEAN = [0.485, 0.456, 0.406]
IMAGENET_STD  = [0.229, 0.224, 0.225]

train_tf = transforms.Compose([
    transforms.RandomResizedCrop(224),        # resize + random crop
    transforms.RandomHorizontalFlip(),        # augmentation: training only
    transforms.ToTensor(),                    # HWC uint8 -> CHW float in [0, 1]
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD),
])

# Validation and test: deterministic, no augmentation
eval_tf = transforms.Compose([
    transforms.Resize(256),                   # short side to 256
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize(IMAGENET_MEAN, IMAGENET_STD),
])

Normalisation subtracts a per-channel mean and divides by a per-channel standard deviation, centring each channel near zero with unit variance. That keeps gradients well-scaled and is the same reasoning behind standardising tabular features in the Encoding module.

Augment training data only

Random crops and flips belong in the training transform. Apply them at validation or test time and your metric changes every time you run it, so you can no longer tell an improvement from noise. The evaluation transform must be deterministic.

11. Data augmentation

Show the model transformed copies of the images you already have, so it learns the object rather than the photograph.

Augmentation is regularisation. If every training photo of a cat faces left, the model can learn "left-facing" as part of "cat". Randomly flipping half of them removes that shortcut. The rule for choosing transforms is simple: the label must survive the transform.

Geometric

Flip, rotate, crop, scale, translate, small perspective warps. Cheap and broadly effective.

Photometric

Brightness, contrast, saturation and hue jitter. Teaches invariance to lighting and camera differences.

Noise and occlusion

Gaussian noise, blur, and random erasing of patches. Forces the model to use more than one cue.

Mixing

Mixup and CutMix blend two images and their labels together. Strong regularisers for large datasets.

import albumentations as A

train_aug = A.Compose([
    A.RandomResizedCrop(224, 224, scale=(0.7, 1.0)),
    A.HorizontalFlip(p=0.5),
    A.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, p=0.5),
    A.GaussNoise(p=0.2),
    A.Normalize(mean=IMAGENET_MEAN, std=IMAGENET_STD),
])

augmented = train_aug(image=rgb_array)["image"]

When a transform destroys the label

Vertical flips break document text and X-rays. Heavy hue jitter breaks any task where colour is the class, like ripe versus unripe fruit. Rotation past a few degrees breaks digit recognition, where a rotated 6 becomes a 9. Always look at a batch of your augmented images before training on them.

Key Concepts

Pixel

One cell of the grid, holding a brightness value per channel. Indexed (row, column) from the top-left.

Bit depth

How many distinct levels a pixel can take. 8-bit gives 256; the data type decides whether arithmetic clips or wraps.

Channel

One full grayscale plane. Stack three for RGB; the count is the size of the channel axis.

Kernel

A small weight matrix slid over the image. Blur, sharpen and edge detection differ only in its numbers.

Interpolation

How resizing invents values it never measured. Nearest for masks, bilinear or bicubic for photographs.

Normalisation

Subtract the channel mean, divide by the channel standard deviation, so inputs are centred and well-scaled.

Best Practices

Do this

  • Print shape, dtype and min/max the moment you load an image — it catches most bugs in one line.
  • Fix channel order at the point of loading, then use one convention everywhere.
  • Use the exact normalisation statistics the pretrained model was trained with.
  • Resize masks with nearest-neighbour so class IDs are never blended.
  • Display a grid of augmented training images before you train on them.
  • Keep the evaluation transform deterministic and identical to what you will run in production.

Avoid this

  • Doing uint8 arithmetic without casting first — it wraps around silently.
  • Assuming cv2.imread gives RGB. It gives BGR.
  • Saving segmentation masks as JPEG.
  • Applying random augmentation at validation or test time.
  • Squashing to a square without checking whether aspect ratio carries information.
  • Computing normalisation statistics over the whole dataset before splitting — that leaks test data into training.
